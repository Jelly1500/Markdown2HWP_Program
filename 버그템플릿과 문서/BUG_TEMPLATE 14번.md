# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서에서 탭과 스페이스가 혼용된 들여쓰기가 있는 텍스트가 한글 문서로 변환될 때 완전히 누락되는 현상이 발생합니다. 특히 시와 같이 의도적인 들여쓰기를 사용하는 문학 작품에서 심각한 문제가 됩니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: 새벽의 창가에서 (시)
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
# 새벽의 창가에서

## 시인의 시선

	푸른빛 낮은 숨결,
	    밤의 경계를 넘어
		희미한 별 그림자.
	        고요가 소리 없이 쌓인다.

    물안개 피어오르듯,
    	기억은 천천히 다가와
		마음의 호수에 잔잔히
			물결을 그린다, 아주 천천히.

	어둠 끝자락에 매달린 새벽,
    바람 한 점 없는 정적 속에서
	    고요히 빛을 기다리는 순간,
        영원의 한 조각을 만난다.

## 짧은 상념

	마음      밭에는
	    생각의      씨앗.

    고요한      새벽엔
    	사색의      꽃이 핀다.

	밤새      내린      이슬처럼     투명한     마음으로,
    오늘     하루도     그렇게     시작되기를.
```

<br><br>

## 어떤 과정에서 버그가 발생했나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 각각의 템플릿으로 변환 테스트 수행
3. 변환 결과 확인:
   - 모든 템플릿에서 동일한 문제 발생:
     * 정상적으로 변환된 부분:
       ```
       # 새벽의 창가에서
       ## 시인의 시선
       ## 짧은 상념
       ```
     * 완전히 누락된 부분:
       - 탭으로 들여쓰기된 모든 시 구절
       - 탭과 스페이스가 혼용된 모든 행
       - 연속된 스페이스가 포함된 행
   - 시의 계층적 구조와 시각적 의도가 완전히 손실됨
   - 실제 시의 내용이 대부분 누락됨

### 예상되는 원인:
1. 마크다운 파서가 탭과 스페이스를 다르게 처리하는 문제
2. 들여쓰기 처리 시 탭을 스페이스로 변환하는 로직 부재
3. 혼용된 공백 문자(탭, 스페이스)를 처리하는 규칙이 없음
4. 연속된 공백 문자를 처리하는 로직이 불완전함
5. 시와 같은 특수한 형식의 들여쓰기를 고려하지 않은 설계
