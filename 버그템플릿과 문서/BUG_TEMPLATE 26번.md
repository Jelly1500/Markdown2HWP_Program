# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서의 **목록 항목 내부에 HTML 태그**(`<u>`, `<font>`, `<span>`, `<div>`, `<mark>`, `<strong>`, `<code>`, `<button>` 등)가 포함되어 있을 때, "**알 수 없는 오류**"가 발생하며 변환이 **완전히 실패**하는 치명적인 문제입니다. 특히 **웹 콘텐츠 작성 가이드라인, 홈페이지 제작 매뉴얼, 웹 디자인 문서** 등에서 HTML 태그 예시나 스타일 지정이 포함된 목록을 사용할 때 이 문제가 발생하며, 웹 관련 업무 문서 작성이 **완전히 불가능**해집니다. 이는 현대적인 웹 문서 작성에 필수적인 HTML 태그 지원 기능의 완전한 부재를 의미하는 심각한 결함입니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: 기관 홈페이지 콘텐츠 작성 가이드라인 (2025년 개정)
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
# 기관 홈페이지 콘텐츠 작성 가이드라인 (2025년 개정)

## 1. 기본 원칙 및 스타일

-   **가독성 확보**
    1.  문장은 간결하고 명확하게 작성합니다: <u><font color="blue">핵심 내용을 쉽게 파악</font></u>할 수 있도록 합니다.
    2.  과도한 전문 용어 사용은 지양합니다: 필요한 경우, <abbr title="예시: 각주 또는 설명글을 통해 부연 설명">용어 해설</abbr>을 제공합니다.
        -   참고: <span style="background-color:yellow;">이해하기 쉬운 단어</span> 선택이 중요합니다.
-   **일관성 유지**
    * 전체 페이지에서 글꼴, 색상, 레이아웃 등의 <del>기존 스타일 가이드</del> <u>개정된 스타일 가이드(본 문서)</u>를 준수합니다.
    * 특히, 제목 스타일은 다음 규칙을 따릅니다:
        <div style="margin-left: 20px; padding: 10px; border: 1px dashed #ccc;">
        <h4>h4 제목 스타일 예시</h4>
        <p>이 구역은 들여쓰기 된 div 태그 내부에 있습니다.<br>
        문단은 p 태그로, 줄바꿈은 br 태그로 처리합니다.</p>
        </div>

## 2. 콘텐츠 유형별 작성 지침

1.  **공지사항**
    -   중요 공지: 제목에 <mark>[중요]</mark> 말머리를 사용하고, 본문 첫 줄은 <strong>굵게</strong> 표시합니다.
    -   첨부파일:
        * 파일명은 `[날짜]_[내용요약].확장자` 형식을 권장합니다.
        * <small>대용량 파일은 별도 링크로 제공할 수 있습니다.</small>
2.  **정책 설명 자료**
    * 도표나 그래프 활용 시: 대체 텍스트(alt text)를 반드시 제공합니다.
        <div style="text-align:center; margin-top:10px; margin-bottom:10px;">
        <em style="color:green;">(예시: 여기에 차트 이미지가 삽입될 수 있습니다 - &lt;img src="..." alt="분기별 성장률 그래프"&gt;)</em>
        </div>
    * 인용문 사용 시: <blockquote><p>국민의 목소리를 경청하는 것이 정책의 시작입니다.</p></blockquote> 형식 또는 마크다운 인용구 사용.
3.  **행사 안내**
    -   일시 및 장소: <b><u>명확하게</u></b> 기재합니다.
    -   참가 신청 링크: 눈에 띄도록 <button type="button" style="background-color:#007bff; color:white; padding:5px 10px; border:none; border-radius:4px;">신청하기</button> 버튼 형태로 제작 가능 (스타일은 CSS로 별도 정의).

## 3. 웹 접근성 준수 사항

-   모든 이미지에는 의미 있는 대체 텍스트를 제공합니다.
-   키보드만으로 모든 기능에 접근 가능해야 합니다.
    1.  <code>&lt;a href="..." tabindex="1"&gt;</code> 와 같이 <code>tabindex</code> 속성을 적절히 활용합니다.
    2.  <span style="text-decoration: underline wavy red;">키보드 포커스</span>가 명확히 보여야 합니다.
```

## 어떤 과정에서 버그가 발생했나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 각각의 템플릿으로 변환 시도
3. 변환 결과 확인:
   - **모든 템플릿에서 동일한 치명적 오류 발생:**
     * "알 수 없는 오류" 메시지 표시
     * HWP 파일이 생성되지 않거나 빈 파일 생성
     * 프로그램이 중단되거나 응답 없음 상태 발생
     * 변환 과정에서 완전히 실패하여 결과물 확인 불가

### 구체적인 문제 상황:
1. **기대되는 결과:**
   - HTML 태그가 적절한 한글 문서 서식으로 변환되어야 함
   - 최소한 HTML 태그를 무시하고라도 텍스트 내용은 변환되어야 함
   - 웹 문서 작성 가이드라인의 기본 내용이 읽기 가능해야 함
   - HTML 예시 코드가 코드 블록이나 일반 텍스트로라도 표시되어야 함

2. **실제 발생하는 결과:**
   - "알 수 없는 오류" 발생으로 변환 완전 실패
   - HWP 파일이 생성되지 않음
   - 프로그램 오류로 인한 중단 또는 무응답
   - 어떤 내용도 확인할 수 없는 완전한 변환 실패
   - 재시도해도 동일한 오류 반복 발생

### 오류를 유발하는 HTML 태그 유형들:
1. **텍스트 서식 태그**
   - `<u>` (밑줄)
   - `<b>`, `<strong>` (굵게)
   - `<i>`, `<em>` (기울임)
   - `<small>` (작은 글씨)
   - `<del>` (취소선)

2. **인라인 스타일 태그**
   - `<font color="blue">` (폰트 색상)
   - `<span style="background-color:yellow;">` (배경색)
   - `<span style="text-decoration: underline wavy red;">` (텍스트 장식)

3. **의미론적 태그**
   - `<abbr title="...">` (약어)
   - `<mark>` (하이라이트)
   - `<code>` (코드)
   - `<blockquote>` (인용구)

4. **블록 레벨 태그**
   - `<div style="...">` (구획)
   - `<h4>` (제목)
   - `<p>` (문단)
   - `<br>` (줄바꿈)

5. **폼 요소 태그**
   - `<button type="button" style="...">` (버튼)
   - 기타 입력 요소들

6. **특수 문자가 포함된 HTML**
   - `&lt;img src="..." alt="..."&gt;` (HTML 엔티티)
   - HTML 태그 예시 코드들

### 특히 문제가 되는 상황:
1. **웹 콘텐츠 작성 가이드라인**
   - HTML 태그 사용 예시가 필수적으로 포함되는 문서
   - 웹 접근성, 스타일 가이드 등을 설명하는 공식 문서
   - 변환 불가로 인해 웹 관련 업무 지침서 작성 완전 봉쇄

2. **홈페이지 제작 매뉴얼**
   - HTML/CSS 코드 예시와 설명이 반드시 필요한 문서
   - 디자인 시스템, UI 가이드라인 등의 전문 문서
   - 웹 개발팀과의 협업 문서 작성 불가능

3. **디지털 정책 문서**
   - 웹 표준, 접근성 준수 방안 등을 다루는 공공 문서
   - 정보화 정책의 기술적 세부사항 설명 문서
   - 디지털 혁신 관련 업무 문서 작성 원천 차단

4. **교육 자료 및 매뉴얼**
   - 직원 대상 웹 콘텐츠 작성 교육 자료
   - 시민 서비스 개선을 위한 웹사이트 운영 가이드
   - 전문성과 정확성이 요구되는 기술 문서 작성 불가

### 예상되는 원인:
1. **HTML 파싱 엔진 부재**
   - 마크다운 파서에서 HTML 태그를 처리하는 기능이 없음
   - HTML 태그를 일반 텍스트로 인식하지 못하고 파싱 오류 발생
   - 복잡한 HTML 구조를 HWPML로 변환하는 로직 부재

2. **태그 중첩 처리 문제**
   - 목록 내부의 HTML 태그 중첩 구조를 처리하지 못함
   - 마크다운과 HTML의 혼합 문법에 대한 예외 처리 부재
   - 복잡한 DOM 구조를 평면적 텍스트로 변환하는 기능 없음

3. **특수 문자 및 엔티티 처리 오류**
   - HTML 엔티티(`&lt;`, `&gt;`, `&amp;` 등) 처리 실패
   - 스타일 속성 내 특수 문자들이 파싱 오류 유발
   - CSS 스타일 구문이 변환 엔진과 충돌

4. **HWPML 서식 매핑 한계**
   - HTML 서식을 HWPML 서식으로 변환하는 매핑 테이블 부재
   - 복잡한 웹 스타일을 한글 문서 서식으로 표현하는 기능 없음
   - 웹 전용 요소들(버튼, 폼 등)에 대한 대체 표현 방안 부재

### 심각도:
- 🐛 심각 (Critical)
- 🚫 변환 실패
- **절대 최고 심각도** - 웹 관련 업무 문서 작성 완전 불가능
- HTML 태그가 포함된 모든 현대적 문서 변환 완전 차단
- 웹 콘텐츠 관리, 디지털 정책 수립 업무 원천 봉쇄
- 모든 템플릿에서 동일한 오류로 대체 방안 전혀 없음
- 공공기관의 디지털 혁신 업무 핵심 기능 무력화
- 웹 표준, 접근성 준수 관련 공식 문서 작성 불가능
- 현대적 문서 작성 트렌드와 완전히 동떨어진 치명적 결함

### 임시 해결 방안:
1. **HTML 태그 완전 제거**
   - 모든 HTML 태그를 변환 전 일반 텍스트로 치환
   - 예: `<strong>굵게</strong>` → `**굵게**` (마크다운 문법으로 변환)
   - 서식 정보는 손실되지만 기본 내용은 변환 가능

2. **HTML 태그를 코드 블록으로 변환**
   - HTML 예시를 백틱(```)으로 감싸서 코드 블록 처리
   - 태그 구조는 유지되지만 서식 효과는 상실
   - 교육 자료에서는 어느 정도 활용 가능

3. **단순 텍스트 치환**
   - HTML 태그를 의미하는 한글로 치환
   - 예: `<u>밑줄</u>` → `[밑줄]밑줄[/밑줄]`
   - 매우 번거롭지만 내용 의미는 보존

### 근본적 해결 방안 제안:
1. **HTML-to-HWPML 변환 엔진 구축**
   - 기본적인 HTML 태그를 한글 문서 서식으로 변환하는 시스템 구현
   - 텍스트 서식 태그 우선 지원 (`<b>`, `<u>`, `<i>`, `<strong>` 등)
   - 점진적으로 지원 태그 범위 확대

2. **HTML 전처리 시스템**
   - HTML 태그를 안전한 플레이스홀더로 치환 후 처리
   - 변환 완료 후 적절한 한글 서식으로 복원
   - 복잡한 태그는 텍스트 형태로 대체 표시

3. **웹 문서 전용 템플릿 개발**
   - HTML 콘텐츠 변환에 특화된 HWPML 템플릿 제작
   - 웹 스타일을 한글 문서 서식으로 매핑하는 전용 변환 로직
   - 코드 블록, 하이라이트, 버튼 등의 대체 표현 방안 구현

4. **사용자 선택형 변환 옵션**
   - HTML 처리 방식을 사용자가 선택할 수 있는 옵션 제공
   - "태그 제거", "코드로 변환", "텍스트로 치환" 등의 선택지
   - 문서 유형에 따른 최적 변환 방식 제안 기능
