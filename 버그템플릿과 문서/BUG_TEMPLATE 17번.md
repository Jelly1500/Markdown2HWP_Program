# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서에서 서식 태그(`, *, **, ~~, _) 내부에 공백이 포함된 텍스트가 있을 경우, 한글 문서로 변환 시 "알 수 없는 오류입니다"라는 메시지와 함께 변환이 완전히 실패하는 심각한 오류가 발생합니다. 이는 문서 작성 시 서식과 공백을 자유롭게 사용할 수 없게 만드는 치명적인 제약사항입니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: 2025년도 정보 시스템 사용자 인터페이스(UI) 개편 안내
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
### 가. 메뉴 구조 및 명칭 변경
- 기존 메뉴: `  행정 지원 시스템  `
- 변경 메뉴: `  **업무 포털** ` (직관성 향상)
    - 세부 기능 중 `  *전자결재 (구)* ` 항목은 ` _통합결재 시스템_ `으로 명칭이 변경 및 통합됩니다.

### 나. 데이터 입력 방식 개선
- 날짜 입력: 기존 `  YYYY / MM / DD  ` 형식에서 `  **YYYY-MM-DD** ` 형식으로 표준화.
    - ~~시간 입력은 변경 없음 (`  HH : MM  `)~~ (정정: 시간 입력도 `HH:MM` 형식으로 통일)
```

<br><br>

## 어떤 과정에서 버그가 발생했나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 각각의 템플릿으로 변환 테스트 수행
3. 변환 결과 확인:
   - 모든 템플릿에서 동일한 문제 발생:
     * "알 수 없는 오류입니다" 메시지 출력
     * 변환 프로세스 완전 실패
     * 어떠한 출력 파일도 생성되지 않음
   - 특히 다음과 같은 패턴에서 오류 발생:
     * 백틱(`) 내부에 공백이 있는 경우
       ```markdown
       `  행정 지원 시스템  `  // 오류 발생
       `행정 지원 시스템`    // 정상 작동
       ```
     * 강조 표시(*) 내부에 공백이 있는 경우
       ```markdown
       `  *전자결재 (구)* `  // 오류 발생
       `*전자결재(구)*`      // 정상 작동
       ```
     * 취소선(~~) 내부에 공백이 있는 경우
     * 밑줄(_) 내부에 공백이 있는 경우
   - 서식 태그 내부의 공백 유무가 변환 성공 여부를 결정하는 핵심 요소로 확인됨

### 예상되는 원인:
1. 마크다운 파서가 서식 태그 내부의 공백을 처리하는 과정에서 예외 발생
2. 공백이 포함된 서식 텍스트를 HWPML로 변환하는 과정에서 치명적 오류 발생
3. 서식 처리 로직이 공백을 포함한 텍스트를 예상하지 못한 설계
4. 공백 문자 처리에 대한 예외 처리 누락
5. 서식 태그와 공백이 조합된 경우의 파싱 규칙 부재

### 심각도:
- 🚫 심각 (Critical)
- 변환 작업 자체가 실패하여 어떠한 결과물도 얻을 수 없음
- 일반적인 문서 작성 패턴을 사용할 수 없는 심각한 제약 발생
- 모든 템플릿에서 동일한 문제가 발생하여 대체 방안 없음
