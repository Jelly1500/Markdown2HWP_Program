# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서에 **ASCII 아트**(텍스트로 그린 그림, 로고, 도표 등)가 포함되어 있을 때, **정확한 공백 배치, 들여쓰기, 특수문자 위치**가 **완전히 무시되거나 변형**되어 **원본의 시각적 형태를 전혀 인식할 수 없게** 되는 심각한 문제입니다. **고정폭 폰트 환경에서 정밀하게 설계된 텍스트 기반 시각적 요소들**이 **한글 문서 변환 과정에서 구조가 완전히 파괴**되어 **기술문서, 개발문서, 시스템 매뉴얼, 프로그래밍 가이드** 등의 **핵심 시각적 정보와 도식화된 설명**이 **완전히 소실**되는 치명적 결함입니다. 이는 **IT 분야, 개발 업무, 기술 지원** 등에서 **필수적으로 사용되는 텍스트 기반 다이어그램과 시각적 표현**의 **완전한 기능 상실**을 의미합니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: ASCII 아트 고양이 그림 포함 문서
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
# ASCII 아트 테스트 문서

## 고양이 ASCII 아트

```
        /\     /\
       {  `---'  }
       {  O   O  }
       ~~>  V  <~~
        \  \|/  /
         `-----'____
         /     \    \_
        {       }\  )_\_   _
        |  \_/  |/ /  \_\_/ )
         \__/  /(_/     \__/
           (__/
```

이 고양이 그림은 ASCII 문자로 그려진 것입니다.
```

## 어떤 과정에서 버그가 발생했나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 각각의 템플릿으로 변환 시도
3. **모든 템플릿에서 동일한 심각한 시각적 오류 발생:**
   - **정확한 공백 배치가 완전히 무시됨**
   - **들여쓰기와 정렬이 무작위로 변형됨**
   - **특수문자들의 상대적 위치 관계 파괴**
   - **원본 ASCII 아트의 시각적 형태 완전 인식 불가**

### 구체적인 문제 상황:
1. **기대되는 결과:**
   ```
           /\     /\
          {  `---'  }
          {  O   O  }
          ~~>  V  <~~
           \  \|/  /
            `-----'____
            /     \    \_
           {       }\  )_\_   _
           |  \_/  |/ /  \_\_/ )
            \__/  /(_/     \__/
              (__/
   ```
   - **정확한 고양이 얼굴과 몸체 형태**가 **명확하게 인식 가능**
   - **각 줄의 정확한 들여쓰기**로 **3차원적 입체감** 표현
   - **특수문자들의 정밀한 배치**로 **귀, 눈, 코, 입, 수염** 등 **세부 특징** 구현

2. **실제 발생하는 결과:**
   ```
   /\     /\
   {  `---'  }
   {  O   O  }
   ~~>  V  <~~
   \  \|/  /
   `-----'____
   /     \    \_
   {       }\  )_\_   _
   |  \_/  |/ /  \_\_/ )
   \__/  /(_/     \__/
   (__/
   ```
   - **모든 줄이 왼쪽 정렬**로 **들여쓰기 정보 완전 소실**
   - **공백 문자들이 무시**되어 **형태 인식 불가능**
   - **특수문자만 남아있어** **무의미한 기호 나열**로 변질
   - **ASCII 아트의 핵심 가치인 시각적 표현 완전 상실**

### 완전히 손실되는 ASCII 아트 구조 요소들:
1. **정밀한 공백 배치**
   - **각 줄의 앞쪽 공백**(들여쓰기)이 **완전히 제거**됨
   - **문자 간 공백**이 **임의로 축소**되거나 **제거**됨
   - **시각적 정렬의 기준점** 완전 소실

2. **들여쓰기 구조**
   - **중앙 정렬 효과**를 위한 **단계별 들여쓰기** 무시
   - **3차원적 입체감** 표현을 위한 **층별 배치** 파괴
   - **시각적 균형**과 **비례감** 완전 상실

3. **특수문자 상대적 위치**
   - **`/\` (귀), `O` (눈), `V` (코), `|/` (수염)** 등의 **정확한 배치** 파괴
   - **얼굴 윤곽**을 형성하는 **`{`, `}`, `~`** 등의 **연결성** 손실
   - **몸체 구조**를 나타내는 **복합 문자 조합** 해체

4. **고정폭 폰트 의존성**
   - **Monospace 폰트 환경**에서만 **정확한 정렬** 가능
   - **비례 폰트 환경**에서 **문자 너비 불일치**로 **구조 왜곡**
   - **한글 문서의 기본 폰트 설정**과 **ASCII 아트 요구사항** 불일치

1. **공백 문자 처리 정책 문제**
   - **마크다운 파싱 과정**에서 **연속 공백 자동 축소**

2. **들여쓰기 인식 한계**
   - **목록이나 인용구가 아닌 일반 텍스트**의 **들여쓰기 무시**
   - **코드 블록 외부**의 **공백 기반 정렬** 미지원
   - **시각적 정렬**과 **논리적 구조** 구분 실패

3. **폰트 및 문자 간격 설정 문제**

   - **특수문자와 일반문자**의 **너비 불일치**

4. **코드 블록 인식 한계**
   - **````와 ```** 사이의 **코드 블록 영역** 정확 파싱 실패
   - **언어 지정이 없는 코드 블록**의 **일반 텍스트 처리**
   - **ASCII 아트 전용 렌더링 모드** 부재

### 임시 해결 방안:
1. **이미지로 변환 후 삽입**
   - **ASCII 아트를 이미지 파일로 캡처** 후 마크다운에 삽입
   ```markdown
   ![고양이 ASCII 아트](cat_ascii.png)
   ```
   - **텍스트 편집 불가능** 및 **검색 기능 상실**

2. **코드 블록 명시적 지정**
   ```markdown
   ```text
   ASCII 아트 내용...
   ```
   ```
   - **일부 공백 보존 가능**하지만 **완전한 해결책 아님**

3. **표(Table) 형태로 변환**
   ```markdown
   | | | | | |
   |---|---|---|---|---|
   | | /\ | | /\ |
   | { | `---' | } |
   ```
   - **표 구조로 인한 복잡성 증가** 및 **편집 어려움**

4. **HTML 직접 사용**
   ```html
   <pre style="font-family: monospace; white-space: pre;">
           /\     /\
          {  `---'  }
          {  O   O  }
   </pre>
   ```
   - **마크다운 철학과 배치** 및 **HTML 지원 한계**

### 근본적 해결 방안 제안:
1. **ASCII 아트 전용 렌더링 모드**
   - **코드 블록 내 ASCII 아트 자동 감지**
   - **고정폭 폰트 강제 적용** 및 **공백 완전 보존**
   - **시각적 정렬을 위한 특별 서식** 제공

2. **공백 및 들여쓰기 완전 보존 옵션**
   - **연속 공백 축소 비활성화** 옵션
   - **들여쓰기 기반 정렬** 완전 지원
   - **사용자 지정 공백 처리 정책**

3. **코드 블록 인식 개선**
   - **````text, ```ascii, ```art** 등의 **특수 언어 태그** 지원
   - **ASCII 아트 최적화된 렌더링** 자동 적용
   - **시각적 효과 보존**을 위한 **전용 스타일** 제공

4. **하이브리드 렌더링 시스템**
   - **일반 텍스트**는 **기존 방식**으로, **ASCII 아트 영역**은 **전용 방식**으로 처리
   - **자동 영역 감지**와 **수동 영역 지정** 모두 지원
   - **최종 문서에서 시각적 일관성** 보장
