# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서에서 인라인 코드(백틱으로 감싼 텍스트)가 한글 문서로 변환될 때 일반 텍스트와 구분되지 않고 동일하게 처리되는 현상이 발생합니다. 코드 블록은 정상적으로 변환되지만, 인라인 코드의 특수 서식이 완전히 무시됩니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: 가위바위보의 역사
3. 사용했던 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
일본에서는 17세기경 `じゃん拳(Janken)`으로 발전하여 오늘날과 유사한 형태를 갖추게 되었습니다.
이때 사용된 기호는 오늘날 `가위(チョキ)`, `바위(グー)`, `보(パー)`와 거의 동일했습니다.

정리하자면, 가위바위보는
- 중국 한나라 시기 `손오공법`에서 시작되어
- 일본 에도 시대의 `じゃん拳(Janken)`으로 발전했으며
- 20세기 이후 서양에 전파되어 `Rock-Paper-Scissors`로 자리 잡은
오랜 역사와 간단함을 겸비한 놀이입니다.
```

<br><br>

## 어떤 과정에서 버그가 발생하였나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 각각의 템플릿으로 변환 테스트 수행
3. 변환 결과 확인:
   - 모든 템플릿에서 동일한 문제 발생:
     * 인라인 코드로 표시된 부분이 일반 텍스트와 동일하게 변환됨
     * 백틱으로 감싼 부분의 특수 서식이 완전히 무시됨
     * 코드 블록은 정상적으로 변환되어 구분됨

### 예상되는 원인:
1. 마크다운 파서가 인라인 코드 태그(``)를 인식하지 못하는 문제
2. HWPML 변환 시 인라인 코드에 대한 특수 서식 처리 로직 부재
3. 인라인 코드와 일반 텍스트를 구분하는 스타일 정의 누락
4. 템플릿의 기본 스타일에 인라인 코드 서식이 정의되지 않음
