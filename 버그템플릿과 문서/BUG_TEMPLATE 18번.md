# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서에서 목록 항목(순서 목록, 비순서 목록) 내부에 코드 블록(```, 언어 지정 포함)이 포함된 경우, 한글 문서로 변환 시 "알 수 없는 오류입니다"라는 메시지와 함께 변환이 완전히 실패하는 심각한 오류가 발생합니다. 이는 기술 문서나 매뉴얼 작성에서 자주 사용되는 중요한 마크다운 패턴을 처리할 수 없게 만드는 치명적인 제약사항입니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: 디지털 예산회계시스템 데이터 입력 지침 (2025년 개정판)
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
# 디지털 예산회계시스템 데이터 입력 지침 (2025년 개정판)

## 1. 기본 입력 원칙
-   **입력 마감 준수:** 각 항목별 입력 마감 기한을 반드시 확인하고 준수합니다.
    -   월별 실적: 익월 3영업일 이내
        ```
        예시: 6월 실적 -> 7월 3일까지 입력 완료
        ```
    -   분기별 보고 자료: 분기 종료 후 10일 이내
-   **데이터 정확성 확보:** 입력 전 반드시 원본 자료와 교차 확인을 거칩니다.
    * 숫자 데이터 입력 시 유의사항:
        1.  천 단위 구분 기호(,)는 시스템에서 자동 입력되므로, 숫자만 연속으로 입력합니다.
            ```text
            올바른 예: 123456789
            잘못된 예: 123,456,789
            ```
        2.  소수점 이하 자릿수는 해당 항목의 지침을 따릅니다.
    * 문자 데이터 입력 시:
        -   특수문자 사용은 최대한 지양합니다. (`&`, `%`, `<`, `>` 등)
        -   부득이하게 사용해야 할 경우, 아래와 같이 대체 표기법을 권장합니다.
            ```
            < -> &lt;
            > -> &gt;
            & -> &amp;
            ```

## 2. 주요 항목별 입력 상세 지침

1.  **사업 코드 입력**
    * 각 사업에 부여된 8자리 고유 코드를 정확히 입력합니다.
        -   예시: `AB25-001Z`
    * 하위 사업의 경우, 상위 사업 코드와의 연계성을 확인해야 합니다.
        ```python
        # 예시: 상위 사업과 하위 사업 코드 구조
        main_project_code = "AB25-000M"
        sub_project_code = "AB25-001Z" # M계열의 하위 Z
        ```

2.  **예산 항목 분류**
    * 예산 과목 코드는 예산편성지침에 명시된 코드를 사용합니다.
        -   비목 분류가 불명확할 경우, 예산팀에 문의 후 입력합니다.
            ```json
            {
              "목": "201",
              "세목": "01",
              "내용": "일반운영비 - 사무용품비",
              "비고": "표준분류코드 참조"
            }
            ```
    * 세부 사업 내역은 구체적으로 작성하며, 다음 양식을 준수합니다.
        ```
        [사업명] OOO 구입 (수량 O개, 단가 OOO원)
        ```

3.  **집행 실적 입력**
    -   실제 집행된 금액과 일자를 기준으로 입력합니다.
    -   증빙자료는 스캔하여 PDF 파일로 첨부하며, 파일명은 아래 규칙을 따릅니다.
        ```
        [날짜]_증빙_[사업코드]_[순번].pdf
        예: 20250603_증빙_AB25-001Z_01.pdf
        ```
```

## 어떤 과정에서 버그가 발생했나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 각각의 템플릿으로 변환 테스트 수행
3. 변환 결과 확인:
   - 모든 템플릿에서 동일한 문제 발생:
     * "알 수 없는 오류입니다" 메시지 출력
     * 변환 프로세스 완전 실패
     * 어떠한 출력 파일도 생성되지 않음
   - 특히 다음과 같은 패턴에서 오류 발생:
     * 목록 항목 내부에 펜스 코드 블록이 있는 경우
       ```markdown
       -   항목 설명
           ```
           코드 예시
           ```
       ```
     * 언어가 지정된 펜스 코드 블록이 목록 내부에 있는 경우
       ```markdown
       1.  설명 텍스트
           ```python
           # 파이썬 코드
           code = "example"
           ```
       ```
     * 중첩된 목록 구조에서 코드 블록이 포함된 경우
     * 인라인 코드(`코드`)는 문제없으나, 펜스 코드 블록(```)에서만 오류 발생

### 확인하고자 했던 기능들 (테스트 불가):
1. 각 목록 항목의 텍스트와 그 안에 포함된 코드 블록 간의 들여쓰기 및 간격 유지 여부
2. 코드 블록 내의 텍스트가 고정폭 글꼴로 표시되는지, 입력된 공백이 보존되는지 여부
3. 펜스 코드 블록에 지정된 언어(python, json, text)가 HWP에서 반영되는지 여부
4. 목록의 중첩 구조(순서 목록 안의 비순서 목록 안의 코드 블록) 표현 정확성

### 예상되는 원인:
1. 마크다운 파서가 목록 내부의 펜스 코드 블록을 올바르게 인식하지 못함
2. 들여쓰기 계산 과정에서 코드 블록의 경계를 잘못 해석하여 파싱 오류 발생
3. 목록 구조와 코드 블록 구조가 중첩될 때 HWPML 변환 로직에서 충돌 발생
4. 언어 지정된 코드 블록 처리 과정에서 예외 처리 누락
5. 목록 내부의 복잡한 블록 요소 처리에 대한 설계 한계

### 심각도:
- 🚫 심각 (Critical)
- 변환 작업 자체가 실패하여 어떠한 결과물도 얻을 수 없음
- 기술 문서, 매뉴얼, 가이드라인 등에서 필수적으로 사용되는 패턴을 처리할 수 없음
- 모든 템플릿에서 동일한 문제가 발생하여 대체 방안 없음
- 실무에서 자주 사용되는 문서 구조를 변환할 수 없는 심각한 제약
