# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서에 **수학 수식($...$, $$...$$)**이 포함되어 있을 때, LaTeX 수식 명령어의 **백슬래시(\\) 문자**들이 Python 정규식 처리 과정에서 **이스케이프 오류**를 발생시켜 변환이 **완전히 실패**하는 **최고 심각도**의 치명적 문제입니다. 특히 `\\times`, `\\sum`, `\\frac`, `\\text` 등의 LaTeX 명령어가 포함된 수식이 있을 때 `re.error: bad escape` 오류가 발생하며, **연구개발 보고서, 학술 문서, 기술 분석 문서** 등에서 필수적인 수식 표현이 완전히 불가능해집니다. 이는 프로그램의 핵심 기능을 무력화시키는 **가장 치명적인 결함**입니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: 2025년도 국가 연구개발사업 투자 효율성 분석 지표
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
# 2025년도 국가 연구개발사업 투자 효율성 분석 지표

## 1. 주요 성과지표 (Key Performance Indicators)

-   **기술적 성공률 (TSR: Technical Success Rate)**
    1.  정의: 계획된 기술 목표 대비 실제 달성된 기술 수준의 비율.
        일반적으로 $TSR = (\text{달성된 기술 수준} / \text{계획된 기술 수준}) \times 100\%$ 로 계산됩니다.
    2.  세부 평가 항목:
        -   핵심 기술 지표 $N$개 중, 목표치 $T_i$ 대비 달성치 $A_i$의 비율을 가중 평균하여 산출.
            가중치를 $w_i$라 할 때 ($\sum_{i=1}^{N} w_i = 1$), 성과 $S = \sum_{i=1}^{N} w_i \frac{A_i}{T_i}$ 로 표현 가능.
        -   특허 출원 및 등록 건수 (국내 $P_d$, 국외 $P_f$).

-   **경제적 기여도 (ECI: Economic Contribution Index)**
    본 지표는 사업의 경제적 파급 효과를 측정하며, 다음과 같은 요소들을 포함합니다.
    * 직접적 경제 효과:
        1.  매출 증대 효과: 사업 결과물의 상용화로 인한 예상 연평균 매출 $R_{avg}$.
        2.  비용 절감 효과: 신기술 적용으로 인한 연평균 비용 절감액 $C_{saved}$.
            이때, 순현재가치(NPV)는 $NPV = \sum_{t=0}^{n} \frac{(R_t - C_t)}{(1+r)^t}$ 공식을 활용하여 분석할 수 있습니다.
    * 간접적 경제 효과 (일자리 창출 등):
        $$
        \Delta E = \alpha \cdot (R_{avg} + C_{saved}) + \beta \cdot N_{jobs}
        $$
        여기서 $\alpha, \beta$는 산업별 가중치이며, $N_{jobs}$는 신규 창출 일자리 수입니다.

-   **사회적 영향력 (SII: Social Impact Index)**
    1.  국민 생활 편익 증진 기여도.
        예: 환경 개선 효과 $E_e = \text{오염물질 감소량 } \Delta P \times \text{사회적 편익 단가 } U_p$.
    2.  국가 위상 제고 및 과학기술 문화 확산 기여도.
        $$
        \text{사회적 총 편익 } B_{total} = \sum (\text{개별 편익 항목}_i)
        $$

## 2. 지표 활용 시 고려사항

-   각 지표의 가중치는 사업 특성 및 단계에 따라 조정될 수 있습니다.
    > 예: 기초 연구 단계에서는 TSR의 가중치를 높이고 ($w_{TSR} > 0.5$), 사업화 단계에서는 ECI의 가중치($w_{ECI}$)를 높일 수 있습니다.
-   데이터 수집의 객관성 및 신뢰성 확보가 중요합니다.
    1.  모든 계산 근거 및 데이터 출처는 명확히 기록되어야 합니다.
        $$
        \text{신뢰도 } R = 1 - \frac{\text{오차 범위 } \epsilon}{\text{측정값 } V}
        $$
    2.  주기적인 지표 점검 및 보완 체계를 마련해야 합니다.
```

## 어떤 과정에서 버그가 발생했나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 각각의 템플릿으로 변환 시도
3. 변환 결과 확인:
   - **모든 템플릿에서 동일한 Python 정규식 오류 발생:**
     * `re.error: bad escape \s at position 6439 (line 5, column 19)`
     * `re.error: bad escape \s at position 7486 (line 5, column 19)`
     * 프로그램이 즉시 중단되며 어떤 결과물도 생성되지 않음
     * 변환 시도 자체가 완전히 불가능

1. **기대되는 결과:**
   - 수학 수식이 적절한 형태로 한글 문서에 변환되어야 함
   - 최소한 수식 부분을 제외하고라도 문서가 변환되어야 함
   - LaTeX 수식이 지원되지 않더라도 텍스트 형태로라도 표시되어야 함

   - 어떤 결과물도 생성되지 않음
   - 재시도해도 동일한 위치에서 반복 오류 발생
   - 수학 수식이 포함된 어떤 문서도 처리할 수 없음

### 오류를 유발하는 LaTeX 명령어들:
1. **수학 연산 기호**
   - `\times` (곱하기)
   - `\div` (나누기)
   - `\pm` (플러스마이너스)
   - `\cdot` (점 곱)

2. **분수 및 지수 표현**
   - `\frac{분자}{분모}` (분수)
   - `^{지수}` (지수)
   - `_{하첨자}` (하첨자)

3. **합계 및 적분 기호**
   - `\sum` (합계)
   - `\int` (적분)
   - `\prod` (곱)
   - `\lim` (극한)

4. **텍스트 삽입 명령어**
   - `\text{텍스트}` (수식 내 텍스트)
   - `\mathrm{텍스트}` (로마체 텍스트)

5. **그리스 문자**
   - `\alpha`, `\beta`, `\gamma` 등
   - `\Delta`, `\Sigma` 등 대문자
   - `\epsilon`, `\theta` 등

6. **기타 수학 기호**
   - `\geq`, `\leq` (부등호)
   - `\neq` (같지 않음)
   - `\approx` (근사)
   - `\infty` (무한대)

### 특히 문제가 되는 상황:
1. **연구개발 보고서**
   - 성과 측정 공식, 효율성 지표 등에 수식 필수 사용
   - 정량적 분석 결과를 수식으로 표현하는 것이 표준
   - 변환 불가로 인해 중요한 연구 결과를 문서화할 수 없음

2. **학술 논문 및 기술 문서**
   - 이론적 배경, 수학적 모델링에 LaTeX 수식 필수
   - 공식 유도 과정, 계산 방법 설명 불가능
   - 학술적 정확성과 전문성 표현 원천 차단

3. **경제 분석 및 통계 보고서**
   - 경제 지표, 통계 공식, 회귀 분석 등에 수식 필수
   - 정량적 분석의 근거와 방법론 제시 불가능
   - 데이터 기반 의사결정 문서 작성 완전 봉쇄

4. **기술 사양서 및 매뉴얼**
   - 엔지니어링 계산, 성능 지표 등에 수식 활용 필수
   - 기술적 정확성과 객관성 표현 불가능
   - 전문 기술 문서의 신뢰성 확보 어려움

### 예상되는 원인:
1. **정규식 이스케이프 처리 문제**
   - LaTeX의 백슬래시(`\`) 문자가 Python 정규식에서 이스케이프 문자로 인식됨
   - `\s` (공백 문자 클래스)로 잘못 해석되어 정규식 오류 발생
   - LaTeX 명령어를 정규식 패턴으로 처리할 때 적절한 이스케이프 처리 부재

2. **수식 파싱 로직 부재**
   - 마크다운 파서에서 수학 수식을 별도로 처리하는 로직이 없음
   - 일반 텍스트와 동일하게 처리하려다 백슬래시 문제 발생
   - MathJax, KaTeX 등 수식 렌더링 엔진과의 연동 부재

3. **HWPML 수식 지원 기능 부족**
   - 한글 문서에서 수식을 표현하는 방법에 대한 연구 부족
   - 수식을 이미지나 특수 객체로 변환하는 기능 부재
   - LaTeX을 HWPML 수식 형식으로 변환하는 매핑 테이블 없음

4. **예외 처리 로직 부재**
   - 수식 처리 과정에서 오류 발생 시 적절한 예외 처리 없음
   - 수식 부분을 건너뛰고 나머지 내용을 처리하는 기능 부재
   - 오류 발생 시 전체 변환 과정이 중단되는 치명적 설계

### 심각도:
- 🐛 심각 (Critical)
- 🚫 변환 실패
- **절대 최고 심각도** - 연구개발, 학술 분야에서 완전히 사용 불가
- 수학 수식이 포함된 모든 문서 변환 완전 차단
- Python 오류로 인한 프로그램 즉시 중단
- 모든 템플릿에서 동일한 오류로 대체 방안 전혀 없음
- 연구개발 업무의 핵심 기능을 완전 무력화
- 학술, 기술, 경제 분야 문서 작성 원천 불가능
- 프로그램의 안정성과 신뢰성을 근본적으로 파괴하는 치명적 결함

### 임시 해결 방안:
1. **수식 완전 제거 후 변환**
   - 모든 `$...$`, `$$...$$` 구문을 변환 전 제거
   - 수식 내용을 일반 텍스트로 수동 변환
   - 문서의 핵심 내용은 크게 손상되지만 기본 변환 가능

2. **수식을 이미지로 대체**
   - LaTeX 수식을 별도 도구로 이미지 생성
   - 마크다운에서 이미지로 교체 후 변환
   - 매우 번거롭지만 수식 표현 유지 가능

3. **백슬래시 이스케이프 처리**
   - 변환 전 모든 백슬래시를 이중 백슬래시로 치환
   - 정규식 오류는 피할 수 있지만 수식 표현 상실

### 근본적 해결 방안 제안:
1. **수식 전처리 시스템 구현**
   - LaTeX 수식을 안전한 플레이스홀더로 치환 후 처리
   - 변환 완료 후 다시 수식 형태로 복원하는 로직 구현
   - 정규식 처리 전에 수식 부분을 별도 보호

2. **MathJax/KaTeX 연동**
   - 웹 기반 수식 렌더링 엔진과 연동하여 이미지 생성
   - 생성된 이미지를 HWPML 객체로 삽입하는 기능 구현
   - 수식의 시각적 품질 보장

3. **HWPML 수식 매핑 시스템**
   - 기본적인 LaTeX 명령어를 한글 수식으로 변환하는 매핑 테이블 구축
   - 복잡한 수식은 텍스트 형태로 대체 표시
   - 한글의 수식 편집기 기능 활용 연구

4. **예외 처리 강화**
   - 수식 처리 과정에서 오류 발생 시 해당 부분만 건너뛰고 계속 진행
   - 사용자에게 수식 처리 불가 부분을 명확히 알림
   - 부분적 변환이라도 가능하도록 안정성 개선
