# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서에 **XML/SVG 형식의 벡터 그래픽 코드**가 포함되어 있을 때, 해당 **SVG 코드가 완전히 무시**되거나 **일반 텍스트로만 처리**되어 **웹 표준 그래픽 요소가 전혀 표시되지 않는** 문제입니다. **SVG(Scalable Vector Graphics)**는 **현대 웹 문서의 핵심 시각적 요소**이며 **공공기관, 기업, 교육기관**에서 **다이어그램, 차트, 로고, 아이콘** 등을 표현하는 **표준 방식**임에도 불구하고 **완전한 지원 부족**으로 **현대적 문서 작성 환경**과의 **호환성 문제**가 발생하는 상황입니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 XML/SVG 코드: 중첩된 주석과 기본 도형 요소 포함
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 XML/SVG 코드:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<svg width="200" height="200" xmlns="http://www.w3.org/2000/svg">
  <!-- Outer comment 시작
    <!-- Inner comment: 이 영역의 사각형(rect)을 비활성화합니다.
      <rect x="20" y="20" width="160" height="160" fill="lightgrey" stroke="black"/>
    -->
    <circle cx="100" cy="100" r="80" fill="gold"/>
  -->
  <text x="10" y="190" font-size="14">주석 중첩 XML/SVG 예시</text>
</svg>
```

<br><br>

## 어떤 과정에서 버그가 발생했나요?

1. 위 XML/SVG 코드를 마크다운 문서에 포함하여 저장
2. 각각의 템플릿으로 변환 시도
3. **모든 템플릿에서 동일한 서식 미지원 문제 발생:**
   - **SVG 코드가 완전히 무시됨**
   - **그래픽 요소가 전혀 표시되지 않음**
   - **일반 텍스트로만 처리**되어 **XML 태그가 그대로 노출**되는 경우 발생

### 구체적인 문제 상황:
1. **기대되는 결과:**
   - **200x200 픽셀 크기의 SVG 캔버스**
   - **금색(gold) 원형 도형** (중심: 100,100, 반지름: 80)
   - **하단에 "주석 중첩 XML/SVG 예시" 텍스트**
   - **벡터 그래픽으로 선명한 시각적 표현**

2. **실제 발생하는 결과:**
   - **SVG 코드가 완전히 무시**되어 **아무것도 표시되지 않음**
   - 또는 **XML 태그가 일반 텍스트로 그대로 노출**
   - **시각적 그래픽 요소 완전 소실**
   - **웹 표준 벡터 그래픽 기능 미지원**

### SVG 코드의 주요 구성요소들:
1. **XML 선언부**
   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   ```
   - **문서 형식과 인코딩** 지정
   - **표준 XML 헤더** 정보

2. **SVG 루트 요소**
   ```xml
   <svg width="200" height="200" xmlns="http://www.w3.org/2000/svg">
   ```
   - **캔버스 크기** (200x200 픽셀)
   - **SVG 네임스페이스** 선언
   - **벡터 그래픽 컨테이너** 역할

3. **중첩된 XML 주석 구조**
   ```xml
   <!-- Outer comment 시작
     <!-- Inner comment: 이 영역의 사각형(rect)을 비활성화합니다.
       <rect x="20" y="20" width="160" height="160" fill="lightgrey" stroke="black"/>
     -->
     <circle cx="100" cy="100" r="80" fill="gold"/>
   -->
   ```
   - **외부 주석** 내에 **내부 주석** 중첩
   - **비활성화된 사각형 요소**
   - **주석 처리된 원형 요소**

4. **활성 텍스트 요소**
   ```xml
   <text x="10" y="190" font-size="14">주석 중첩 XML/SVG 예시</text>
   ```
   - **텍스트 위치** (x=10, y=190)
   - **폰트 크기** (14px)
   - **한글 텍스트 내용**

### 완전히 지원되지 않는 SVG 기능들:
1. **기본 도형 요소**
   - **`<circle>`, `<rect>`, `<ellipse>`, `<line>`, `<polygon>`** 등
   - **좌표계 기반 정밀한 위치 지정**
   - **색상, 크기, 스타일 속성**

2. **텍스트 및 타이포그래피**
   - **`<text>`, `<tspan>`** 요소
   - **폰트 설정**, **텍스트 정렬**, **회전** 등
   - **벡터 기반 텍스트 렌더링**

3. **고급 그래픽 기능**
   - **`<path>`** 요소의 **복잡한 경로 정의**
   - **`<g>`** 요소의 **그룹화**
   - **변환(transform)**, **애니메이션** 등

4. **스타일링 및 효과**
   - **CSS 스타일 적용**
   - **그라디언트**, **패턴**, **필터** 효과
   - **투명도**, **그림자** 등 시각 효과

### 특히 문제가 되는 상황:
1. **공공기관 및 정부 문서**
   - **조직도**, **업무 프로세스 차트**, **통계 그래프** 등
   - **정책 설명 다이어그램**, **시설 배치도** 등
   - **웹 접근성 준수**를 위한 **벡터 그래픽 활용**

2. **기업 및 비즈니스 문서**
   - **회사 로고**, **브랜드 아이덴티티** 요소
   - **플로우차트**, **조직 구조도**, **프로젝트 타임라인** 등
   - **프레젠테이션용 벡터 그래픽**

3. **교육 및 학술 자료**
   - **수학 도형**, **과학 실험 장치도**, **지리 지도** 등
   - **교육용 다이어그램**, **학습 보조 시각 자료**
   - **논문 및 연구 보고서**의 **도식화된 설명**

4. **기술 문서 및 매뉴얼**
   - **소프트웨어 아키텍처 다이어그램**
   - **하드웨어 회로도**, **시스템 구성도** 등
   - **API 문서**의 **데이터 플로우 차트**

5. **웹 및 디지털 미디어**
   - **반응형 아이콘**, **로고**, **일러스트레이션**
   - **인터랙티브 차트**, **데이터 시각화**
   - **모던 웹 표준** 기반 **그래픽 요소**

### 예상되는 원인:
1. **SVG 파싱 엔진 부재**
   - **XML 파서**의 **SVG 특화 처리** 기능 부족
   - **벡터 그래픽 렌더링** 엔진 미구현
   - **웹 표준 그래픽 지원** 체계 부재

2. **마크다운 확장 기능 한계**
   - **인라인 HTML/XML** 처리 능력 제한
   - **코드 블록 외부 XML** 인식 실패
   - **MIME 타입 기반 콘텐츠** 분류 부재

3. **한글 문서 포맷 제약**
   - **HWP 포맷**의 **벡터 그래픽 지원** 범위
   - **이미지 변환** 과정의 **복잡성**
   - **문서 호환성** 우선 정책

4. **렌더링 파이프라인 미구축**
   - **SVG → 래스터 이미지** 변환 기능 부재
   - **벡터 → 벡터** 포맷 변환 시스템 부재
   - **실시간 그래픽 렌더링** 환경 부족

### 심각도:
- 🐛 중간 (Medium)
- 📝 서식 미지원 (Format Not Supported)
- **중간 심각도** - 현대적 문서 작성의 핵심 기능 부재
- **웹 표준 호환성** 문제
- **디지털 문서화 환경**과의 **격차 확대**
- **시각적 커뮤니케이션** 도구 활용 제약
- **국제 표준 그래픽 포맷** 지원 부족
- **현대적 업무 환경** 요구사항 미충족

### 임시 해결 방안:
1. **SVG를 PNG/JPG로 사전 변환**
   - **온라인 SVG 변환 도구** 활용
   ```
   SVG 코드 → 온라인 컨버터 → PNG 이미지 → 마크다운 삽입
   ```
   - **해상도 손실** 및 **벡터 특성 상실**

2. **코드 블록으로 SVG 코드 보존**
   ```markdown
   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <svg width="200" height="200" xmlns="http://www.w3.org/2000/svg">
     <!-- SVG 내용 -->
   </svg>
   ```
   ```
   - **코드로만 표시**되어 **실제 그래픽 표현 불가**

3. **HTML img 태그 활용**
   ```html
   <img src="data:image/svg+xml;base64,[SVG_BASE64_DATA]" alt="SVG 그래픽"/>
   ```
   - **Base64 인코딩** 복잡성 및 **HTML 지원 의존성**

4. **외부 이미지 파일 참조**
   ```markdown
   ![SVG 그래픽](diagram.svg)
   ```
   - **파일 관리 복잡성** 및 **포터빌리티 저하**

### 근본적 해결 방안 제안:
1. **SVG 렌더링 엔진 통합**
   - **오픈소스 SVG 라이브러리** 도입
   - **SVG → PNG/PDF** 자동 변환 시스템
   - **벡터 그래픽 최적화** 렌더링

2. **웹 표준 그래픽 지원 체계**
   - **HTML5 Canvas**, **WebGL** 등 **모던 그래픽 API** 지원
   - **CSS3**, **SVG 애니메이션** 등 **동적 요소** 처리
   - **반응형 그래픽** 및 **다중 해상도** 지원

3. **하이브리드 문서 포맷**
   - **HWP 포맷 + 웹 기술** 결합
   - **임베디드 웹뷰** 기반 **그래픽 렌더링**
   - **문서 호환성** 유지하면서 **현대적 기능** 확장

4. **플러그인 아키텍처**
   - **그래픽 처리 플러그인** 시스템 구축
   - **사용자 정의 렌더러** 추가 가능
   - **확장 가능한 문서 변환** 파이프라인
