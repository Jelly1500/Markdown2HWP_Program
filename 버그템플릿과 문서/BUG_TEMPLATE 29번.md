# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서의 **순서 목록(ordered list)에서 사용자가 의도적으로 설정한 번호**가 완전히 무시되고, **자동으로 순차 번호(1,2,3...)가 부여**되는 시각적 오류입니다. 사용자가 `1. 5. 3.`과 같이 특정 번호 순서를 의도했음에도 불구하고 변환된 문서에서는 `1. 2. 3.`으로 **강제로 재정렬**되어 **문서의 원래 의도와 구조가 완전히 왜곡**됩니다. 이는 **문서 초안, 수정 과정, 참조 번호 체계, 법령 조항 번호** 등을 다루는 공공 문서에서 매우 치명적인 문제로, **번호 체계의 일관성과 정확성**이 핵심인 업무 문서의 신뢰성을 심각하게 훼손합니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: 2025년 신규 직원 교육 프로그램 단계별 진행안 (초안)
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
# 2025년 신규 직원 교육 프로그램 단계별 진행안 (초안)

## 제1부: 기본 소양 교육 (1주차)

1.  **기관 소개 및 비전 공유**
    - 기관의 역사, 주요 기능, 조직 문화 등을 소개합니다.
    - 기관장 환영사 및 질의응답 시간 포함.

5.  **공직 윤리 및 행동 강령 교육** (← 1번 다음에 와야 할 내용이지만, 소스 번호는 5번)
    - 청렴 의무, 비밀 엄수, 이해충돌 방지 등 주요 내용을 다룹니다.
    1.  사례 중심 교육
        9.  실제 발생 가능한 다양한 윤리적 딜레마 상황 제시
        2.  분임 토의 및 발표 (← 9번 다음에 오지만, 소스 번호는 2번)
    4.  관련 법규 해설

3.  **정보 보안 및 개인정보보호 교육** (← 5번 다음에 와야 할 내용이지만, 소스 번호는 3번)
    - 개인정보보호법 주요 내용 및 정보 시스템 보안 수칙 교육.

## 제2부: 직무 기초 교육 (2주차 - 3주차)

7.  **부서별 공통 직무 교육**
    1.  주요 업무 시스템 사용법 (예: 전자결재, 예산회계 시스템)
        1.  계정 신청 및 초기 설정
        1.  주요 기능 시연 및 실습 (← 앞 항목과 번호가 같음)
    3.  문서 작성 및 보고 표준 교육

2.  **배치 부서 심화 직무 교육 (OJT)** (← 7번 다음에 와야 할 내용이지만, 소스 번호는 2번)
    - 멘토 지정 및 개별 학습 계획 수립.
    - 실제 업무 참여를 통한 실습 위주 교육.
        4.  일일 업무 보고서 작성 및 피드백
        1.  주간 단위 학습 성과 평가

## 제3부: 종합 평가 및 수료 (4주차)

1.  **종합 직무 능력 평가**
    - 필기시험 및 실기 평가.

1.  **교육 결과 피드백 및 면담** (← 앞 항목과 번호가 같음)
    - 개인별 강점 및 보완점 컨설팅.

6.  **수료식 및 정규 발령** (← 1번 다음에 와야 할 내용이지만, 소스 번호는 6번)
```

## 어떤 과정에서 버그가 발생했나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 각각의 템플릿으로 변환 시도
3. 변환 결과 확인:
   - **모든 템플릿에서 동일한 시각적 오류 발생:**
     * **사용자 지정 번호가 완전히 무시됨**
     * **자동으로 순차 번호(1,2,3...)가 강제 부여됨**
     * **문서의 원래 구조와 의도가 완전히 왜곡됨**
     * **번호 참조가 맞지 않아 문서 내용이 혼란스러워짐**

### 구체적인 문제 상황:
1. **기대되는 결과:**
   - **제1부에서**: `1. 기관 소개` → `5. 공직 윤리` → `3. 정보 보안` 순서로 표시
   - **제2부에서**: `7. 부서별 공통 직무` → `2. 배치 부서 심화 직무` 순서로 표시
   - **제3부에서**: `1. 종합 직무 능력 평가` → `1. 교육 결과 피드백` → `6. 수료식` 순서로 표시
   - **중첩 목록에서**: `1. 사례 중심` → `9. 실제 발생 가능한` → `2. 분임 토의` 순서로 표시
   - 사용자가 **의도한 번호 체계가 그대로 유지**되어야 함

2. **실제 발생하는 결과:**
   - **제1부에서**: `1. 기관 소개` → `2. 공직 윤리` → `3. 정보 보안` (자동 순차 번호)
   - **제2부에서**: `1. 부서별 공통 직무` → `2. 배치 부서 심화 직무` (자동 순차 번호)
   - **제3부에서**: `1. 종합 직무 능력 평가` → `2. 교육 결과 피드백` → `3. 수료식` (자동 순차 번호)
   - **중첩 목록에서**: `1. 사례 중심` → `2. 실제 발생 가능한` → `3. 분임 토의` (자동 순차 번호)
   - **모든 사용자 지정 번호가 무시되고 강제 재정렬**됨

### 구체적인 번호 왜곡 사례들:
1. **제1부 기본 소양 교육**
   ```
   원본: 1. → 5. → 3. (의도된 순서)
   결과: 1. → 2. → 3. (강제 순차 번호)
   ```

2. **제2부 직무 기초 교육**
   ```
   원본: 7. → 2. (의도된 순서)
   결과: 1. → 2. (강제 순차 번호)
   ```

3. **중첩 목록 내부**
   ```
   원본: 1. → 9. → 2. → 4. (의도된 순서)
   결과: 1. → 2. → 3. → 4. (강제 순차 번호)
   ```

4. **동일 번호 사용 케이스**
   ```
   원본: 1. → 1. → 6. (의도적 중복)
   결과: 1. → 2. → 3. (중복 무시하고 순차 번호)
   ```

### 특히 문제가 되는 상황:
1. **문서 초안 및 수정 과정**
   - 초안 단계에서 **항목 순서를 임시로 조정**하거나 **특정 번호를 유지**해야 하는 경우
   - 검토 과정에서 **"5번 항목 참고"** 등의 **내부 참조가 무의미**해짐
   - **수정 이력 추적**이나 **버전 관리** 과정에서 **번호 체계 혼란** 발생

2. **법령 및 규정 문서**
   - **조항 번호, 항 번호**가 법적 의미를 갖는 문서에서 치명적
   - **"제5조", "제3항"** 등의 **정확한 번호 참조가 필수**인 문서
   - 번호 왜곡으로 인한 **법적 효력 상실** 우려

3. **참조 번호 체계가 있는 업무 매뉴얼**
   - **"앞서 9번에서 언급한"**, **"5번 절차에 따라"** 등의 **상호 참조 체계** 붕괴
   - **업무 프로세스의 순서와 번호**가 일치하지 않아 **실무 혼란** 발생
   - **교육 자료에서 단계별 번호의 의미** 완전히 상실

4. **회의록 및 안건 문서**
   - **"안건 5번"**, **"의결사항 3번"** 등의 **공식 번호**가 변경되어 **회의 기록 왜곡**
   - **후속 조치나 추적 관리**에서 **번호 불일치로 인한 업무 착오** 발생
   - **공식 문서의 정확성과 신뢰성** 심각하게 훼손

### 예상되는 원인:
1. **마크다운 파서의 자동 번호 부여 정책**
   - 마크다운 파서가 **순서 목록을 자동으로 1,2,3... 순서로 재정렬**하는 기본 설정
   - **사용자 지정 번호를 무시**하고 **순차적 번호를 강제 적용**하는 로직
   - **HTML 변환 과정에서 ol(ordered list) 태그의 기본 동작** 적용

2. **HWPML 변환 과정의 번호 처리 오류**
   - 마크다운에서 HWPML로 변환할 때 **번호 정보 손실**
   - **한글 문서의 번호 목록 기능**이 **자동 번호 부여 방식**으로만 구현
   - **사용자 지정 번호를 수동 설정**하는 기능 부재

3. **목록 구조 해석의 한계**
   - **순서 목록과 번호 없는 목록**을 구분하지 못함
   - **사용자가 의도한 번호 체계**를 **파악하고 유지**하는 로직 부재
   - **번호의 의미와 맥락**을 이해하지 못하는 단순 파싱

4. **번호 중복 및 불규칙 순서 처리 실패**
   - **동일 번호 사용**(1. → 1. → 6.)에 대한 **예외 처리 부재**
   - **불규칙한 번호 순서**(1. → 5. → 3.)에 대한 **적절한 대응 방안 없음**
   - **복잡한 번호 체계**를 **단순 순차 목록으로 치환**하는 근본적 한계

### 심각도:
- 🐛 중간 (Moderate)
- 🎨 시각적 오류
- **문서 구조와 의도 심각 왜곡**
- **번호 참조 체계의 완전한 붕괴**
- **법령, 규정, 매뉴얼 등 번호가 중요한 문서**에서 치명적 문제
- **문서 작성자의 의도와 완전히 다른 결과물** 생성
- **업무 프로세스와 문서 번호 불일치**로 인한 실무 혼란
- **공식 문서의 정확성과 신뢰성** 심각 훼손
- 모든 템플릿에서 동일한 문제로 **대체 방안 없음**

### 임시 해결 방안:
1. **번호 없는 목록으로 변경 후 수동 번호 추가**
   - 순서 목록 대신 `-` 또는 `*`를 사용한 번호 없는 목록 사용
   - 각 항목 앞에 **수동으로 번호를 텍스트로 추가**: `- 5. 공직 윤리 교육`
   - 번호 체계는 유지되지만 **자동 번호 목록의 장점 상실**

2. **HTML 태그 직접 사용**
   - 마크다운 대신 **HTML의 `<ol>` 태그와 `start`, `value` 속성** 사용
   - 예: `<ol start="5"><li>공직 윤리 교육</li></ol>`
   - 복잡하고 가독성이 떨어지지만 **정확한 번호 제어 가능**

3. **문서 분할 후 개별 변환**
   - **각 섹션을 별도 파일로 분할**하여 번호 충돌 회피
   - 각 파일에서는 **1번부터 시작하는 순차 번호** 사용
   - 최종 취합 시 **수동으로 번호 조정** 필요

4. **번호를 텍스트 내용에 포함**
   - 순서 목록 기능을 포기하고 **제목이나 내용에 번호 포함**
   - 예: `- **5. 공직 윤리 및 행동 강령 교육**`
   - **목록 기능은 상실**되지만 **번호 정보는 보존**

### 근본적 해결 방안 제안:
1. **사용자 지정 번호 인식 시스템 구현**
   - 마크다운 파서에서 **사용자가 지정한 번호를 인식하고 보존**하는 기능
   - **자동 순차 번호와 사용자 지정 번호를 구분**하는 옵션 제공
   - **번호 순서 유지 모드**와 **자동 정렬 모드** 선택 가능

2. **HWPML 번호 목록 고급 제어 기능**
   - 한글 문서에서 **사용자 지정 번호**를 설정할 수 있는 HWPML 구조 활용
   - **수동 번호 입력**, **시작 번호 지정**, **번호 건너뛰기** 등의 기능 구현
   - **복잡한 번호 체계도 정확히 표현**할 수 있는 변환 시스템

3. **번호 체계 분석 및 보존 알고리즘**
   - 문서 전체를 분석하여 **사용자의 번호 체계 의도를 파악**
   - **참조 번호와 실제 번호의 일치성** 검증 및 **경고 시스템**
   - **번호 체계의 일관성**을 유지하면서 **의도를 최대한 반영**하는 변환

4. **번호 처리 옵션 및 프리뷰 기능**
   - **"번호 유지"**, **"자동 정렬"**, **"하이브리드"** 등 다양한 처리 방식 제공
   - 변환 전 **번호 처리 결과를 미리보기**로 확인할 수 있는 기능
   - **번호 충돌이나 불일치**를 사전에 감지하고 **사용자에게 알리는 시스템**
