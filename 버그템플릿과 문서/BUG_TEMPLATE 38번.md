# 버그 리포트

## 어떤 버그인가요?

> 마크다운 문서에 **Mermaid 문법으로 작성된 다이어그램**(플로우차트, 시퀀스 다이어그램, 간트 차트, 조직도, 상태 다이어그램 등)이 포함되어 있을 때, 해당 **다이어그램이 완전히 무시**되거나 **일반 텍스트로만 처리**되어 **시각적 표현이 전혀 생성되지 않는** 심각한 문제입니다. **Mermaid**는 **현대적 문서화의 핵심 도구**이며 **공공기관, 기업, 교육기관**에서 **업무 흐름도, 시스템 아키텍처, 프로세스 설계도** 등을 표현하는 **국제 표준 방식**임에도 불구하고 **완전한 지원 부족**으로 **업무 문서화의 핵심 기능**이 **원천적으로 불가능**한 치명적 결함입니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 Mermaid 다이어그램: 민원 처리 시스템 업무 흐름도
3. 테스트한 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 Mermaid 다이어그램 코드:
```mermaid
graph TD;
    A[민원인: 온라인/방문 접수] --> B{1단계: 민원 분류 및 담당자 지정};
    B -- 단순 민원 --> C[해당 부서: 즉시 처리];
    C --> F[처리 결과 통보 (SMS/이메일)];
    B -- 복합 민원 --> D[관련 부서 협의 요청];
    D --> E[종합 검토 및 처리 방안 수립];
    E --> F;
    F --> G((완료 및 종결));

    style A fill:#e6f3ff,stroke:#333,stroke-width:2px
    style G fill:#d4edda,stroke:#333,stroke-width:2px
```

## 어떤 과정에서 버그가 발생했나요?

1. 위 Mermaid 다이어그램 코드를 마크다운 문서에 포함하여 저장
2. 각각의 템플릿으로 변환 시도
3. **모든 템플릿에서 동일한 심각한 서식 미지원 문제 발생:**
   - **Mermaid 다이어그램이 완전히 무시됨**
   - **시각적 흐름도가 전혀 생성되지 않음**
   - **일반 텍스트로만 처리**되어 **다이어그램 구조 완전 상실**
   - **업무 프로세스의 시각적 이해 불가능**

### 구체적인 문제 상황:
1. **기대되는 결과:**
   - **민원인 접수** → **민원 분류** → **처리 방식 분기** → **결과 통보** → **완료**의 **시각적 플로우차트**
   - **사각형 노드**: `A[민원인: 온라인/방문 접수]`, `C[해당 부서: 즉시 처리]` 등
   - **다이아몬드 분기점**: `B{1단계: 민원 분류 및 담당자 지정}` 
   - **원형 종료점**: `G((완료 및 종결))`
   - **화살표 연결선**: `-->`, `-- 단순 민원 -->`, `-- 복합 민원 -->` 등
   - **색상 스타일링**: 시작점은 **파란색**, 종료점은 **녹색** 배경
   - **전체적인 상하좌우 흐름 구조**가 **직관적으로 파악 가능**

2. **실제 발생하는 결과:**
   - **모든 Mermaid 코드가 일반 텍스트로 표시**
   ```
   graph TD;
   A[민원인: 온라인/방문 접수] --> B{1단계: 민원 분류 및 담당자 지정};
   B -- 단순 민원 --> C[해당 부서: 즉시 처리];
   ...
   ```
   - **시각적 다이어그램 완전 소실**
   - **업무 흐름의 직관적 이해 불가능**
   - **프로세스 분기점과 연결 관계 파악 극도로 어려움**

### 손실되는 핵심 Mermaid 다이어그램 요소들:
1. **노드 (Node) 타입별 시각화**
   ```mermaid
   # 기대: 각기 다른 모양의 노드
   A[사각형 노드]           # 일반 프로세스
   B{다이아몬드 분기점}     # 의사결정 포인트  
   C((원형 시작/종료))     # 시작점/종료점
   D[("원형 텍스트")]      # 특수 원형 노드
   E>"비대칭 노드"]        # 특별 표시
   
   # 실제: 모든 텍스트 동일하게 표시
   A[사각형 노드]           # 구분 없음
   B{다이아몬드 분기점}     # 구분 없음
   C((원형 시작/종료))     # 구분 없음
   ```

2. **연결선 (Edge) 및 라벨링**
   ```mermaid
   # 기대: 다양한 화살표와 라벨
   A --> B                 # 기본 화살표
   B -- 조건1 --> C        # 라벨이 있는 화살표
   B -- 조건2 --> D        # 분기 라벨
   C -.-> E                # 점선 화살표
   D ==> F                 # 굵은 화살표
   
   # 실제: 텍스트로만 표시
   A --> B                 # 화살표 없음
   B -- 조건1 --> C        # 연결 관계 불명확
   ```

3. **스타일링 및 색상 적용**
   ```mermaid
   # 기대: 색상과 스타일 적용
   style A fill:#e6f3ff,stroke:#333,stroke-width:2px    # 파란 배경
   style G fill:#d4edda,stroke:#333,stroke-width:2px    # 녹색 배경
   classDef urgent fill:#ff9999                         # 긴급 클래스
   
   # 실제: 스타일 완전 무시
   style A fill:#e6f3ff,stroke:#333,stroke-width:2px    # 일반 텍스트
   style G fill:#d4edda,stroke:#333,stroke-width:2px    # 효과 없음
   ```

4. **다이어그램 방향 및 레이아웃**
   ```mermaid
   # 기대: 다양한 레이아웃 방향
   graph TD    # Top Down (위에서 아래로)
   graph LR    # Left to Right (왼쪽에서 오른쪽)
   graph RL    # Right to Left (오른쪽에서 왼쪽)
   graph BT    # Bottom to Top (아래에서 위로)
   
   # 실제: 방향성 완전 무시
   graph TD    # 단순 텍스트
   ```

### 지원되지 않는 주요 Mermaid 다이어그램 타입들:
1. **플로우차트 (Flowchart)**
   ```mermaid
   graph TD
       A[Start] --> B{Is it?}
       B -->|Yes| C[OK]
       B -->|No| D[End]
   ```
   - **업무 프로세스**, **의사결정 트리**, **시스템 흐름도**

2. **시퀀스 다이어그램 (Sequence Diagram)**
   ```mermaid
   sequenceDiagram
       participant A as 민원인
       participant B as 접수창구
       participant C as 담당부서
       A->>B: 민원 제출
       B->>C: 업무 이관
       C->>B: 처리 결과
       B->>A: 결과 통보
   ```
   - **시스템 간 상호작용**, **API 호출 흐름**, **업무 절차**

3. **간트 차트 (Gantt Chart)**
   ```mermaid
   gantt
       title 프로젝트 일정표
       section 분석
       요구사항 분석    :a1, 2024-01-01, 30d
       시스템 설계      :a2, after a1, 20d
       section 개발
       개발 단계       :b1, after a2, 45d
       테스트         :b2, after b1, 15d
   ```
   - **프로젝트 관리**, **일정 계획**, **업무 스케줄링**

4. **상태 다이어그램 (State Diagram)**
   ```mermaid
   stateDiagram-v2
       [*] --> 민원접수
       민원접수 --> 검토중
       검토중 --> 처리중
       처리중 --> 완료
       완료 --> [*]
   ```
   - **시스템 상태 변화**, **업무 단계**, **라이프사이클**

5. **클래스 다이어그램 (Class Diagram)**
   ```mermaid
   classDiagram
       class 민원관리시스템 {
           +민원번호: String
           +접수일자: Date
           +처리상태: Status
           +접수하기()
           +처리하기()
       }
   ```
   - **시스템 설계**, **데이터 구조**, **객체 관계**

- **공공기관 업무 프로세스 문서화** 기능 마비
- **기업 비즈니스 프로세스 모델링** 불가능

- **프로젝트 관리 및 계획** 도구 활용 제약
- **국제 표준 다이어그램 도구**와 **완전 단절**
- **현대적 협업 환경** 요구사항 미충족

### 임시 해결 방안:
1. **외부 Mermaid 렌더러 사용**
   - **온라인 Mermaid Live Editor**에서 **PNG/SVG 생성**
   ```
   Mermaid 코드 → Mermaid Live → PNG 다운로드 → 마크다운 삽입
   ```
   - **수작업 과정 복잡** 및 **실시간 수정 어려움**

2. **그래픽 도구로 수동 작성**
   - **Visio**, **Draw.io**, **Lucidchart** 등으로 **직접 다이어그램 작성**
   - **텍스트 기반 버전 관리 불가능** 및 **유지보수 어려움**

3. **코드 블록으로 구조만 보존**
   ```
   ```mermaid
   graph TD;
   A[Start] --> B{Decision}
   B --> C[End]
   ```
   ```
   - **구조는 보존**되지만 **시각적 표현 완전 부재**

4. **ASCII 다이어그램으로 대체**
   ```
   [Start] → [Decision] → [End]
      ↓         ↓
   [Process] → [Result]
   ```
   - **극도로 제한적 표현** 및 **복잡한 구조 불가능**

### 근본적 해결 방안 제안:
1. **Mermaid 렌더링 엔진 통합**
