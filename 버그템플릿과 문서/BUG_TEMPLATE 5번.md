# 버그 리포트

## 어떤 버그인가요?

> 마크다운에서 '>', '>>' 등으로 표현되는 중첩된 인용구의 깊이가 한글 문서로 변환 시 모두 동일한 수준으로 처리되어, 원본의 계층 구조가 손실되는 현상이 발생합니다.

<br><br>

## 어떤 상황에서 겪으셨나요?

1. 실행 환경: Windows 10, Python 가상환경
2. 테스트를 수행한 마크다운 문서: 중첩 인용구 테스트
3. 사용했던 템플릿: 
   - template_ex_01.hml
   - template_ex_02.hml
   - template_ex_03.hml
   - 새템플릿.hml
   - 템플릿문서.hml
   - 템플릿문서1.hml

테스트한 마크다운 텍스트:
```markdown
> "페이커(이상혁)는 e스포츠 역사상 가장 성공적인 리그 오브 레전드 선수로 평가받는다.  
> 
> > "2013년 SK텔레콤 T1에 입단한 이후, 그는 놀라운 기량으로 단숨에 주목을 받았다.  
> > 
> > > "데뷔 시즌부터 미드 라인에서 독보적인 플레이를 선보이며, 초창기부터 'GOAT(역대 최고)'라는 별명을 얻게 되었다.  
> > > 
> > > > "2013, 2015, 2016 월드 챔피언십 우승을 이끌었고, SK텔레콤 T1을 리그 오브 레전드의 전설로 만들었다.  
```

<br><br>

## 어떤 과정에서 버그가 발생하였나요?

1. 위 마크다운 텍스트를 파일로 저장
2. 프로그램을 통해 한글 문서로 변환
3. 변환 결과 확인:
   - 원본: 4단계의 깊이를 가진 인용구 구조
   - 결과: 모든 인용구가 동일한 들여쓰기 수준으로 변환됨
   - 깊이에 따른 시각적 구분이 전혀 없음

### 예상되는 원인:
1. 마크다운 파서가 중첩 수준('>>', '>>>' 등)을 제대로 인식하지 못함
2. HWPML 변환 과정에서 인용구의 깊이 정보가 손실됨
3. 한글 문서의 인용구 스타일이 깊이를 표현하도록 설정되지 않음
